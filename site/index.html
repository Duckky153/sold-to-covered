Catch it before it moves.

Evals: the sample day was made with planted problems and an answer key the checks never see. A run passes only if every planted problem is found and no clean order is flagged. That proves the checks catch every kind of problem they are built for. It is not a measure of accuracy on real orders.

The checks

The checks, kept as data

Each check is one entry in checks.json: the fields it reads, the rule, who fixes it and the next step. One small engine runs every check on every order. A new check that uses an existing kind of rule is one more entry.

Problems found after binding

A problem found after binding means a customer who thought they were covered gets a call to fix it. Counted 30 days after each week, because these problems take time to surface. Includes problems the seven checks do not look for. Simulated.

What changed, and why

    Dismissals show which check is wrong

    When people keep dismissing one check for the same reason, the check is wrong, not the people. That is how the subjectivities check got fixed on Oct 13.
